  demo.gif / .mp4   트랙 A + 더미 있는 문서만. 720px, 0.5초 간격 ≤40프레임, 하단 자막 3줄
  manifest.json     파일·크기 · demo 상태 · warnings · 게시 체크리스트(전부 false 시작)

### 설계상 하지 않는 것 3가지

1. **`post_en.md` 를 생성하지 않는다.** 마케팅 문안의 기계 번역은 기계 번역처럼 읽히고,
   이 프로젝트의 영어판은 번역이 아니라 병행 재작성이다(랜딩 3페이지와 같은 판단).
   없으면 경고만 남긴다. ep01~03 은 **손으로 영어판을 썼다**.
2. **본문을 고치지 않는다.** 금지 규칙 위반은 **보고하고 아무 파일도 쓰지 않고 exit 1**.
   정규식을 만족시키려고 남의 문장을 고쳐 쓰면 아무도 고르지 않은 카피가 나간다.
3. **140자 초과 트윗을 자르지 않는다.** 바이트 경계에서 자른 문장은 저자가 쓰지 않은
   문장이고, 올라간 뒤에는 보이지 않는다. 글자 수를 옆에 적어 **올리기 전에** 보이게 한다.

### 금지 규칙 (스크립트가 강제)

frontmatter + 본문 전체를 검사한다. 하나라도 걸리면 아무것도 쓰지 않고 exit 1:

| 규칙 | 근거 |
|---|---|
| `タイムズカー` 불사용 | 전략 v2 / 시장결정 v2 — 사건명 금지 |
| `絶対` · `唯一` · `必ず安全` · `防ぎます/防げます` | 「原則 / リスクを下げる / 確認する」로 |
| `一括処理` · `一括ダウンロード` | 미출시 기능 홍보 금지 |
| 본문에 `提出先の指示を必ず確認してください` 필수 | 모든 How-to |

1인칭 피해담과 「긴 변 ≤800px 축소 삽화」는 **정규식으로 판정할 수 없어** 코드 가드가
없다 — 그 둘은 README 와 topics.json `_forbidden` 에 규칙으로만 적혀 있고, 사람이 지킨다.
**가드가 있는 것과 없는 것을 구별해 적어두는 것이 이 표의 목적이다.**

## 5. 검수 포인트

### 캐러셀
- **글자 잘림이 아니라 축소로 맞춘다.** 2%씩 줄여 52% 바닥까지 가고, 그래도 넘치면
  `warnings` 에 적는다. 세 편 모두 **100%** 로 들어갔다(축소 0회).
  `overflow:hidden` 을 쓰지 않은 이유: 문장 끝이 사라진 채로 완성된 이미지처럼 보이는 것이
  실제로 올라가는 실패 모양이다.
- 하단 「提出先の指示を必ず確認してください。」는 **슬라이드 크롬**이다 — 본문이 빠뜨려도
  3장 전부에 나온다.
- 확인할 것: URL 박스의 줄바꿈이 읽히는지(ep02 는 `…&ut / m_campaign=ep02` 로 끊긴다 — 읽히지만
  미관상 아쉬움), 제목 3줄짜리(ep01)가 답답하지 않은지.

### 데모 GIF
- **0.5초 간격 / 최대 40프레임은 지키되, 연속 20초가 아니라 단계별로 나눠 찍는다.**
  촬영풍 JPG 의 OCR 에 수십 초가 걸려서, 한 번에 연속으로 찍으면 **40프레임 전부가 진행
  바**가 되고 완성된 GIF 에 문서가 한 장도 안 나온다. 업로드 4 → 탐지 결과 10 → 목적 바 6 →
  결과 나머지로 쪼갰다. 지시서 수치에서 **의도적으로 벗어난 유일한 지점**이다.
- 자막은 **페이지 안에 주입한 DOM 바**로 넣는다. ffmpeg `drawtext` 로 넣으면 일본어 폰트
  경로를 스크립트에 박아야 하고 문구가 두 군데 살게 된다.
- 확인할 것: 자막 3줄이 아래 바 안에 들어가는지 · 마지막 프레임이 결과 화면인지 ·
  **띠 아래 원문이 비치지 않는지**. 마지막 항목은 캡처 품질이 아니라 제품 문제이므로,
  비치면 GIF 를 다시 찍을 것이 아니라 골든을 의심해야 한다.
- 실측 확인(프레임 추출): 2프레임째에 記号·番号·枝番·保険者番号·二次元コード 가 전부 띠로
  덮이고 氏名·生年月日·住所·事業所名称 가 남아 있다. 마지막 프레임은 평탄화 결과 화면 +
  「このファイルは画像に平坦化され、黒いボックスの下に原文は残りません。」 문구.

### X 스레드
- `⚠ OVER` 가 하나라도 있으면 그대로 올리지 않는다. 세 편 모두 최장 95자(ep02 CTA 트윗,
  UTM URL 포함)로 140자 이내.

### 빌드하다 잡은 자기 결함 2건

1. 🔴 **정적 서버가 디렉터리 요청에 404 를 돌려줬다.** 첫 ep01 실행의 데모가
   `page.setInputFiles: Timeout … waiting for locator('#fileInput')` 로 죽었는데,
   진짜 원인은 `/safe/` 가 404 였던 것이다 — **사실이지만 쓸모없는 에러 메시지**였다.
   실제 앱은 `ActionDispatch::Static` 이 `<dir>/index.html` 을 돌려주므로, 하네스 서버가
   그러지 않으면 **에러 페이지를 녹화한 GIF** 가 나온다.
   → 디렉터리면 `index.html` 로 해석하고, **goto 직후에 응답 코드와 `#fileInput` 존재를
   먼저 단언**한다. 30초 뒤 셀렉터에서 죽는 대신 그 자리에서 상태 코드와 함께 실패한다.
2. **playwright 가 CJS 라 `import()` 결과가 `.default` 밑에 온다.** `chromium` 을 네임스페이스에서
   바로 읽으면 `undefined` 이고, 실패는 30줄 뒤 `Cannot read properties of undefined` 로 나타난다
   (실측). 두 경로(패키지 해석 / 골든 하네스의 설치본) 모두 정규화해서 읽는다.
   playwright 사본을 따로 만들지 않은 이유는 **버전이 조용히 갈라지는 것**을 막기 위해서다.

## 8. 미완·판단 보류

- **ep04~ep33 본문 미작성.** 지시서 범위는 첫 3편이다. 주제·랜딩·purpose·주차는 전부
  `topics.json` 에 확정돼 있다.
- **게시 0건.** `manifest.json` 의 `posted` 는 네 채널 전부 `false`, `topics.json` 의
  `status` 는 전부 `draft`. 게시는 사람이 한다(README §게시 절차).
- **코드 가드가 없는 규칙 2개**: 1인칭 피해담 금지 · 더미 카드 이미지 축소(긴 변 ≤800px).
  정규식으로 판정할 수 없어 사람이 지킨다. 세 편 모두 1인칭 피해담 없음, 카드 이미지 미삽입.
- **ep05·ep06 의 「電子入札の容量制限」·「補助金精算」은 아직 근거가 약하다.** 전략 문서가
  근거 등급을 매기지 않은 신규 주제이고, 실제 용량 상한 수치나 정산 요령의 문구를 확인하지
  않았다. 본문을 쓰기 전에 발주처 공고를 1건 이상 확인할 것.
- **생성물(PNG/GIF/MP4)을 git 에 커밋한다.** 3편에 약 1.5MB, 33편이면 30MB 전후가 된다.
  올린 자산을 그대로 보관하는 쪽이 지금은 유용하다고 판단했으나, 저장소가 무거워지면
  **GIF/MP4 가 가장 먼저 뺄 대상**이다(한 명령으로 재생성된다 — 단 폰트·브라우저 버전이
  달라지면 바이트는 달라진다).
- **`x_thread.md` 는 X 의 URL 단축(t.co 23자)을 고려하지 않고 생 URL 글자 수를 센다.**
  보수적인 방향이라 그대로 뒀다 — 실제로는 더 여유가 있다.
- **캐러셀의 Instagram 규격만 맞췄다**(1080×1350). YouTube Shorts 썸네일·Reels 세로 포맷은
  별도이며 이번 범위 밖이다.
