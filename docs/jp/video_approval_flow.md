## Gate 1 — 기획 승인 (주초)

### 왜 여기서 한 번 받는가

Gate 1 에서 정해지는 세 가지는 **뒤에서 바꾸면 전부 다시 만들어야 하는 것**들이다:

- **hook** 은 기사 리드이자 X 스레드 1행이자 쇼츠 첫 5초이자 썸네일 문구의 출발점이다.
  고치면 `post_ja.md` → `x_thread.md` → `shorts.mp4` → 썸네일이 연쇄로 다시 만들어진다.
- **썸네일** 은 쇼츠 **끝 화면**에 들어간다. 바꾸면 영상을 다시 렌더한다.
- **주제·intent** 는 썸네일 틀을 결정한다(理由/手順/比較).

토요일에 처음 보여주면 그 연쇄가 토요일 밤에 일어난다.

### 산출물 — `content/jp/epNN/plan_ko.md`

**0번 조사에서 공용 승인 대시보드를 찾지 못했다**
([`video_team_reuse.md`](video_team_reuse.md): 내일앨범에 `.claude/agents/` 도 영상 승인
화면도 없었고, `post :approve` 는 학급 사진 승인이라 도메인이 다르다).
그래서 Gate 1 은 **파일 하나**다. 화면을 새로 만들지 않은 이유는 아래 「왜 4회가 아닌가」와
같다 — 승인 장치를 늘리는 비용이 승인 품질보다 먼저 오른다.

`plan_ko.md` 가 담는 것:

1. 주제 한 줄 + intent + 왜 이 회차인가
2. **hook 3안** — 각각 다른 각도. 추천 1개와 근거
3. **썸네일 2안** — 파일 경로와 차이(문구·강조 위치)
4. **사람이 판단할 한 가지** — 에이전트가 판단할 수 없는 것 딱 하나
5. 승인 기록 필드(아래)

### 승인 기록 — 「고른 것」과 「기본값」을 구별한다

```
승인: [ ] hook A / [ ] B / [ ] C      승인일: ____
썸네일: [ ] a / [ ] b                  승인자: ____
```

고른 뒤 반영하는 곳:

| 고른 것 | 어디에 적는가 | 그 다음 |
|---|---|---|
| hook | `content/jp/epNN/post_ja.md` 의 frontmatter `hook` | `make_short.mjs NN` 재실행 |
| 썸네일 | `content/jp/epNN/short_ja.json` 의 `cover`, **그리고 `cover_provisional` 삭제** | 같음 |

🔴 **`cover_provisional: true` 는 「아직 고르지 않았다」는 뜻이다.** 빌드가 돌아야 하므로
잠정값을 허용하지만, 그 상태로 도는 **매 실행이 경고를 낸다**. 기본값이 조용해지는 순간
그 기본값이 결정이 된다 — 그래서 사람이 플래그를 지울 때까지 시끄럽다.

## Gate 2 — 최종 승인 (토요일)

**기존 화면을 그대로 쓴다**: `/admin/jp/packages`.
이번 세션은 **서버 화면을 바꾸지 않았고 배포도 하지 않았다.**

승인은 **한 버전을 동결**한다(S8). 승인 지문이 어긋나면 12:00 JST 에 게시가 **차단**된다.

### 쇼츠·썸네일·긴 영상을 이 화면에 추가하는 건 — 설계 메모만 (S10 백로그)

지금 이 화면은 블로그 본문 · X 스레드 · LinkedIn · 한국어 요약을 보여준다.
영상은 안 보인다. 추가하려면:

- `JpEpisodeSource` 가 `short_ja.json` · `thumbnails.json` 을 읽어 패키지에 싣는다
- 뷰에 `<video>` 1개 + 썸네일 2장 + 끝 화면 프레임 초
- **승인 지문(`content_hash`)에 영상 자산을 포함할지**가 진짜 결정이다.
  포함하면 쇼츠를 다시 렌더할 때마다 승인이 깨진다(ffmpeg 출력은 바이트가
  결정적이지 않다 — 같은 입력으로 다시 돌려도 같은 파일이 아니다).
  **포함한다면 바이트가 아니라 `short_ja.json` 의 선언값**(duration·cover·
  rendered_segments)을 지문에 넣어야 한다.

→ **이번 범위 밖**(지시: 「S10 설계 메모로만 남긴다(서버 화면 변경·배포 금지)」).

## 왜 단계별 4회 승인을 하지 않는가

후보는 ① 기획 ② 대본 ③ 썸네일 ④ 최종 이었다. **2회로 줄였다.**

**1. 승인 횟수를 늘리면 승인의 질이 떨어진다.** 승인자는 한 사람이고 주 1편이 돈다.
주 4회 승인 요청은 「또 왔네」가 되고, 그 다음은 보지 않고 누르는 것이다. 이 저장소는
같은 모양의 실패를 이미 적어뒀다 — **지울 것이 없는데 승인을 요청하면 사람을 훈련시켜
다음 승인을 무심하게 만든다**(전역 삭제 정책).

**2. ②대본과 ③썸네일은 ①의 hook 에서 파생된다.** hook 이 정해지면 대본의 4구간은
`lib/shorts.mjs` 의 고정 구조이고(pain/why/fix/done/end), 썸네일 문구는 그 hook 의
12자 압축이다. **독립적으로 승인할 거리가 없다** — 승인 항목이 아니라 확인 항목이다.

**3. ④최종이 ②③을 이미 포함한다.** 토요일 화면에 완성본이 있다. 중간 승인은
「같은 것을 두 번 본다」가 되기 쉽다.

**4. 그래서 남긴 2회는 성격이 다르다.**

| | Gate 1 | Gate 2 |
|---|---|---|
| 묻는 것 | **무엇을 만들까** | **이대로 내보낼까** |
| 바꾸는 비용 | 싸다(아직 안 만들었다) | 비싸다(연쇄 재생성) |
| 안 하면 | 토요일 밤에 전부 다시 만든다 | 검토 없이 공개된다 |

**되돌릴 수 없는 지점 앞에 하나씩** — 그게 2회인 이유다.

## 이 흐름이 **막는** 실패

| 실패 | 어디서 막히나 |
|---|---|
| 아무도 안 고른 hook 이 4개 채널로 나간다 | Gate 1 |
| 썸네일 기본값이 조용히 결정이 된다 | `cover_provisional` 경고 |
| 승인한 것과 다른 버전이 게시된다 | Gate 2 지문(S8) |
| 일본어를 읽지 못하는 승인자가 형식적으로 누른다 | 두 게이트 다 **한국어** |

## 막지 **못하는** 것 (알고 두는 것)

- **쇼츠 영상 자체는 Gate 2 화면에 안 보인다**(위 설계 메모). 지금은 승인자가
  파일을 직접 열어야 하고, 안 열어도 승인은 된다.
- Gate 1 은 파일이라 **알림이 없다.** 주초에 누가 말해줘야 한다.
- `plan_ko.md` 에 승인 기록을 적는 것도 **사람 손**이다 — 안 적으면 「언제 승인됐는지」가
  남지 않는다. 지문이 있는 Gate 2 와 달리 Gate 1 은 기계가 강제하지 않는다.
