## B. 블로그 JA 트랙 (DB·모델·라우트)
4. 마이그레이션: `posts`에 `title_ja:string subtitle_ja:string body_ja:text meta_description_ja:string primary_locale:string(default "ko", null:false) content_track:string content_ep:integer package:jsonb(default {})`. **기존 행은 모두 `primary_locale='ko'`로 채워지는지 마이그레이션 안에서 assert**. `posts` 에 `[content_track, content_ep]` **unique 인덱스**(NULL 허용, partial `WHERE content_track IS NOT NULL`) — 이것이 (jp, ep) 고유성의 DB 보장이다. `blog_topics`에 `track:string(default "ko")`, `ep:integer`, `title_en`, `doc`, `purpose`, `landing`, `publish_on:date`, `verify_before:boolean(default false)`, `verified_at:datetime`, `social_skip:boolean(default false)`. 인덱스 `[track, ep]` unique(ep null 허용). CHECK 제약 `primary_locale IN ('ko','ja')`.
5. `Post`: 불변식을 `validate :primary_title_and_body_present, if: published`(title_·body_ 둘 다 `primary_locale` 기준)로 — `validates :title_ko, presence: true`는 `if: -> { primary_locale == "ko" }` 로 조건화. `primary_locale` inclusion `%w[ko ja]`. `scope :jp`. `indexable_locales` = **기존 `indexable?` 가드 유지** + 해당 로케일 본문 존재. KO 글(primary ko)은 결과·순서까지 현재와 동일(E-1). JA 글: canonical·x-default = `/ja/blog/:slug`, draft/scheduled는 noindex·hreflang 빈 목록. `generate_slug`는 `primary_locale=ja`면 호출하지 않는다(slug는 import가 명시 부여, 이후 변경 금지 — `slug` 변경 시 validation error for ja).
6. `BlogTopic`: `scope :jp`, **`scope :next_jp, -> { jp.where(review_sent_at: nil).where("publish_on <= ?", 9.days.from_now).order(:publish_on, :ep) }`** — `used`는 jp 트랙에서 쓰지 않는다(의미 혼동 방지; 컬럼 `review_sent_at:datetime` 추가). 기존 `category` 검증에 `privacy` 추가. `track` inclusion `%w[ko jp]`. **KO 잡은 `BlogTopic.where(track:"ko").unused`로 고정**(테스트 필수).
7. 라우트/컨트롤러: `/blog/:slug`가 `primary_locale=ja` 글이면 `/ja/blog/:slug` 301. `/ja/blog`(index)는 `Post.jp.published`. `/ja/blog/:slug`는 ja 본문 렌더(noindex 없음), `/en/blog/:slug`는 body_en 있으면 렌더. ko 글의 `/ja/blog/:slug` 폴백(KO 본문+noindex)은 **현행 유지**. sitemap에 `/ja/blog/` 글 포함. JSON-LD Article(`inLanguage: "ja"`) + FAQPage(package.faq 3문, 있을 때만). og:locale `ja_JP`, og:image=hero.
8. `rake content:jp_import[NN]`(lib/tasks/content.rake): `content/jp/epNN/`에서 post_ja.md(frontmatter+본문→body_ja는 markdown→HTML, 기존 변환 경로 재사용), post_en.md, x_thread.md, faq_ja.md(있으면), carousel_1.png(hero), demo.gif/mp4(`package_assets` has_many_attached), manifest.json을 읽어 `Post`를 **`(content_track='jp', content_ep=NN)` 키로 upsert**: `find_or_create_by!` + `RecordNotUnique` rescue → 재조회(동시 실행 안전). slug는 **생성 시 1회만** `jp-ep{NN}-{title_en kebab 40자}`, 이후 불변. **갱신 허용 조건: `status=='draft' && package['approved_at'].nil?`** — 그 외(approved_at 있음/scheduled/published)는 아무것도 쓰지 않고 `package['import_conflict']={at, content_hash}` 만 기록, 종료 코드 2, stderr에 「승인된 패키지와 충돌 — admin에서 差し戻し 후 재실행」. `package` 갱신은 **키 단위 merge**(`x`·`posted`·`approved_at`·`approved_version`·`guard` 는 import가 절대 쓰지 않음). `package` = `{ep, track, content_hash, x_thread:[...5~6], x_reply_en, linkedin_text, captions, faq, utm, assets:[...], imported_at}`. `linkedin_text` 자동 조립 규칙은 그대로(≤1,300자).
9. `JpContentGuard`(app/services/jp_content_guard.rb): `content/jp/guard_rules.json`을 읽어 v3.1 §3-4 검사 — 금지어·우회표현(JA/EN), 필수문(독립 행 + 「。」), 제목 32자, **트윗 가중 길이는 `twitter-text` gem(또는 동일 알고리즘 포팅: CJK 2·URL 23·결합 이모지)으로 계산해 편집 기준 140 초과를 위반으로**, LinkedIn 1,300, FAQ 3, **법적 주장 문장(〜が求められ|〜制限され|〜義務|〜法)이 있으면 같은 글에 `e-gov.go.jp` 또는 `*.go.jp` 원문 URL + 확인일(確認日: YYYY-MM-DD) 존재** — 없으면 위반(手順형 글에 법령을 억지로 붙이지 말라는 뜻이지 URL을 붙이라는 뜻이 아님; 법적 주장 자체가 없으면 통과), 「あなた」, 「弊社|当社」. 결과 `package.guard = {violations, checked_at}`. 위반이 있어도 import는 하되 승인 버튼 비활성. 자동 수정 금지.

13. `BlogMailer.jp_review_requested`: 제목 `[SafeFile JP] 第NN回 承認依頼: {title_ja}`. 본문(노션 스타일: 아이콘·굵기·빈 줄): 미리보기 링크 `/admin/jp/packages/:ep` · guard 위반 목록(빨강) · 블로그 게시 예정(JST) · X 게시 예정(JST) · **X 스레드 5줄 전문 + 영어 답글** · **LinkedIn 본문 전문(복사용)** · KPI 대조표(P1/P10/P15/P16/P17 현재값 vs 예측, `safe:jp_weekly` 산출 재사용; 값이 없으면 「—」) · 남은 jp 토픽 수.
14. `Admin::JpPackagesController#show`(`/admin/jp/packages/:ep`, 기존 admin 인증): 글 JA(렌더)·EN·카루셀 3·GIF·X 스레드(트윗별 가중 길이 표시)·LinkedIn·FAQ·게시 예정 시각(블로그·X)·guard 결과·import_conflict 경고·KPI 표를 한 페이지에. 버튼 **「承認」** = 트랜잭션으로 `status: scheduled` + `package.approved_at` + **`package.approved_version = SHA256(title_ja+body_ja+body_en+x_thread+linkedin_text+assets digest+published_at)`** + `package.x = {state:'pending', due_at: published_at+3h}` (guard 위반·import_conflict·`verify_before && !verified_at` 이면 비활성). 「差し戻す」= draft + `approved_at/approved_version` 삭제 + `x.state='cancelled'`. `verify_before` 토픽에는 「確認済みにする」 버튼(→ `verified_at`). 기존 `improve` 링크 유지하되 **approved_at 있으면 improve 금지**(먼저 差し戻す). `/admin/posts`에 `primary_locale` 뱃지 + jp 필터.
15. `XPublishJob`(신규): `PublishScheduledPostsJob#publish` 성공 직후 `primary_locale=='ja' && package.x&.state=='pending'` 이면 enqueue(`wait_until: x.due_at`) — **enqueue 실패해도 `x.state='pending'`이 DB에 남아 `rake blog:x_pending`으로 재enqueue 가능**. 잡 본체: ① `approved_version` 재계산 일치 확인(불일치 → `x.state='blocked'`, 메일) ② `x.state='running'` + 잠금(`with_lock`, 동시 실행 금지) ③ `package.x.tweets[]` = 승인된 배열 전체(5~6 JA + EN 답글) 각 `{seq, text_sha, tweet_id:nil, parent_id:nil, state}` ④ 미완료 중 **첫 항목부터** 순차 게시: 1트윗째 미디어(demo.gif 우선, 없으면 carousel_1) 업로드 → `POST /2/tweets`(`reply.in_reply_to_tweet_id`=직전 tweet_id) → **성공 응답 즉시 `tweet_id`·`parent_id`·`state='done'`을 update_column**. 응답 유실(타임아웃·5xx 후 불명)은 해당 seq `state='unknown'`으로 두고 **잡 중단**(자동 재전송 금지, 메일로 사람 확인 요청; admin에서 「送信済みとして記録」/「未送信として再開」 중 택1). 네트워크 오류 전 명확한 4xx는 `state='failed'`+`x.error`, `retry_on` 3회. ⑤ 전부 done → `x.state='done'`, `x.url`(1번 트윗), `posted.x=true`. 키는 ENV `X_API_KEY X_API_SECRET X_ACCESS_TOKEN X_ACCESS_SECRET`; 없거나 `X_API_DRY_RUN=1`이면 로그만 + `x.dry_run=true`. 미디어 업로드 엔드포인트는 **v2 `POST /2/media/upload`를 우선 시도하고 실패 시 v1.1 `media/upload`** — 둘 다 실패면 텍스트만 게시하지 말고 `state='failed'`. gem은 추가하지 말고 `Net::HTTP` + OAuth 1.0a 서명을 `lib/x_client.rb`에 직접. 보고서에 「실제 계정의 요금제·월 쓰기 한도·미디어 업로드 권한을 확인하기 전에는 `X_API_DRY_RUN=1` 유지」를 명시.
