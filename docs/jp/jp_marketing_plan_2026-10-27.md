핵심 판단 두 가지:
1. **"바이럴"이 실제로 가능한 면은 YouTube Shorts 하나다.** X 신규 계정은 수 주간 추천 노출이 제한되고 팔로워 0이라 퍼질 수 없다. 블로그는 검색(느리지만 복리). LinkedIn은 Justin 개인 브랜드. Shorts만 팔로워 0에서도 알고리즘이 밀어준다. → **영상 포맷을 Shorts 기준으로 다시 정하고, 채널 개설을 1순위로.**
2. **지금 영상은 "사용법 녹화"지 "문제 해결 장면"이 아니다.** 퍼지는 건 "あるある(공감) 15초 + 해결 10초"다. 화면 녹화는 그 안의 해결 10초로만 쓴다.

## 1. 영상 포맷 — 「문제 → 해결」 30초 Shorts (전 회차 공통)

```
0~5초   문제 장면 (텍스트 카드, 큰 글씨, 1문장)   예) 「黒塗り、一箇所残ってた」→「差し戻し」
5~10초  왜 그런가 (카드 1장 또는 실패 장면)       예) PDFの黒い四角 → コピーすると文字が出る
10~25초 해결 (실제 화면 녹화, 자막 3줄)            드래그 → 목적 선택 → 저장
25~30초 결과 + 한 줄 (「ファイルは外に出ません」) + 랜딩 URL 카드
```
- 세로 1080×1920, 자막 JA(영어판은 같은 녹화 + EN 자막 1벌 더), 음성 없음(또는 일본어 TTS 선택).
- 제작은 전부 `make_episode.mjs`에서: 카드는 HTML 템플릿, 해결 장면은 지금 Playwright 녹화(세로 뷰포트로 변경), 합치기는 ffmpeg. **촬영·편집 사람 손 0.**
- 트랙 B(해설형)는 해결 장면 대신 "비교 카드"(예: 付箋 vs 검은 띠 vs 평탄화) 3장 전환으로 같은 30초.
- 1편에서 **Shorts 1 + GIF(X용, 가로 720) 1 + 카루셀 3 + 가이드 PDF** 가 나온다. 원본은 하나.

| 일 | 어느 쪽 | 비고 |

| YouTube 채널 개설·Shorts 업로드(API 전까지 수동)·설명란·썸네일 | **SNS 운영 프로젝트** | 자산은 `content/jp/epNN/shorts_ja.mp4` 로 받음 |
| X 팔로우·답글·DM 응대 | SNS 운영 프로젝트 | 매주 20~30분 |
| LinkedIn 개발 일지 게시 | SNS 운영 프로젝트(Justin 본인) | 승인 메일의 본문·PDF |
| 메타(IG/FB) | 보류 — 손대지 않음 | |
| 성과 수집(YouTube 조회·X 노출) → `safe:jp_weekly` 수동 입력 | SNS 운영 프로젝트 | 월 22일 예측 리뷰 전 |

## 6. 바이럴을 위해 콘텐츠 자체에서 바꿀 것 (S10 반영)

1. **첫 줄은 항상 상대의 고통** — 글·트윗·Shorts 공통. 「黒塗り一箇所残って差し戻し」「免許証の写真、そのまま送っていませんか」. 기능·"무료"로 시작 금지.
2. **1편 = 1문제**. 두 문제 섞지 않는다(topics.json의 ep12·13처럼 원인 설명형은 "왜 복원되나" 1개로).
3. **Shorts 제목은 질문형 JA 20자 내** + 해시태그 3(#入札 #黒塗り #本人確認 류). 썸네일 = 문제 카드 1장.
4. **댓글 유도 문장** 1개를 Shorts 끝과 X 마지막 트윗에: 「あなたの提出先はどう指示していますか？」 — 답글이 ep33 소재가 된다.
5. **영어판 Shorts는 在留カード·パスポート 회차(ep21·22)에 집중** — 일본 거주 외국인은 영어 검색이 많고 경쟁 콘텐츠가 적다.
6. 광고 집행 없음(예측 보고서 원칙). 바이럴은 Shorts 알고리즘 + 업계 계정 답글만.
