# docs/jp/metrics/

`bin/rails safe:jp_weekly` 가 쓰는 주차별 집계 파일(`YYYY-WW.md`)이 쌓이는 곳.

```
bin/rails safe:jp_weekly              # 최근 7일 → 현재 ISO 주차 파일
bin/rails "safe:jp_weekly[2026-W43]"  # 주차를 직접 지정
```

읽는 법과 함정은 생성 파일 머리말에 매번 다시 적힌다. 요점만:

- **이벤트 수이고 사용자 수가 아니다.** `safe_events` 에 방문자를 식별하는 열이 없다
  (IP·해시·쿠키 전부 없음). 그래서 중복 제거가 불가능하다 — 그것이 이 설계의 목적이다.
- **0건은 세 가지를 뜻할 수 있다**: 트래픽이 없었다 / 엔드포인트가 422 로 거부하고 있다 /
  배포본에 계측 코드가 없다. 생성 파일이 그 세 가지를 나란히 적는 이유다.
  구별은 서버 로그로만 된다.
- 파일럿 신청 수는 여기 없다. 그것은 `jp_pilot_requests`(개인정보)이고 이 폴더와 섞지 않는다.

이 폴더는 비어 있어도 삭제하지 않는다 — 태스크가 `mkdir_p` 하지만, 폴더가 git 에 있어야
"아직 한 주도 안 돌렸다"와 "폴더가 사라졌다"가 구별된다.
