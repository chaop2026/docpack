## (a) 공유 URL 에서 `utm_` 폐기 → `?via=x&ep=NN`

**왜**: Justin 의 Chrome(차단 확장)에서 `?utm_*` 이 붙은 주소가 **브라우저 단계에서 차단**된다
(서버는 정상 200). 저자가 자기 공유 링크를 열 수 없는 계측은 계측이 아니다.

### 바꾸는 곳 (전수)

| 위치 | 지금 | 뒤 |
|---|---|---|
| `jp_episode_source.rb#utm_url` | `?utm_source=x&utm_medium=social&utm_campaign=epNN` | `?via=x&ep=NN` |
| `jp_episode_source.rb#blog_url` | `?utm_source=linkedin&…` | `?via=linkedin&ep=NN` |
| `make_episode.mjs` `utmUrl`·`LINKEDIN_UTM` | 〃 | 〃 |
| `posts/_jp_article.html.erb` | 본문 CTA 의 `utm_source=blog&…` | `?via=blog&ep=NN` |
| `public/safe/jp/jp.js` | `?utm_source` 만 읽음 | **`?via` 우선, 없으면 `?utm_source`** |
| `SafeEvent::VALUES`·`KEYS` | `utm_source` | `via`·`ep` **추가**, `utm_source` **유지** |
| `JpWeeklyKpi#p16`·`lines` | `utm_source` 집계 | **두 차원 합산** |
| 콘텐츠 3편의 `x_thread.md`·`linkedin_en.md`·`manifest.json` | utm | via (재빌드로) |

### 설계 결정 두 가지

1. **`utm_source` 키를 지우지 않는다.** 이미 저장된 행이 있고, 밖에 나간 옛 링크(블로그 본문·
   10-24 이전 트윗)가 계속 그 파라미터로 도착한다. 지우면 그 방문이 `none` 으로 떨어져
   **「유입이 줄었다」로 보이는데 실제로는 측정을 그만둔 것**이다. 새 키 `via` 를 더하고
   KPI 가 **둘을 합산**한다(s9_todo §S10-8 의 「기존 utm 이벤트는 그대로 두고 새 키로 합산」).
2. **`ep` 는 새 차원이다.** 지금 `utm_campaign` 은 URL 에만 있고 **저장되지 않는다**(KEYS 밖).
   회차별 유입을 처음으로 볼 수 있게 되지만, `SafeEvent` 의 전제가 「카테고리 값만 저장」이므로
   **`ep01`~`ep33` 고정 목록**으로 받는다. 범위 밖은 `other`.

### 하지 않는 것
- 기존 `safe_events` 행 수정·마이그레이션. 과거는 과거다.
- `?via=` 를 리다이렉트로 `?utm_source=` 에 매핑하는 일. 그러면 차단이 그대로다.

**왜**: 마케팅 계획 §6-1. 지금 ep01 의 첫 줄은 「입찰 서류 반송의 **대부분은**…」 으로 시작해

- `guard_rules.json` 에 X 전용 규칙 추가. `linkedin` 섹션과 같은 구조(해당 면에만 적용).
- `jp_content_strategy_v3.md` §3-3 X 행에 반영(개정 날짜 명기, 기존 행은 ~~취소선~~ 금지 —
  이 표는 행 교체가 관례).
- ep02·ep03 `x_thread.md` 재작성 → **`post_ja.md` 의 frontmatter `hook` 을 고쳐 재빌드**한다.
  `x_thread.md` 는 생성물이므로 직접 고치면 다음 빌드가 되돌린다.

> ⚠️ **규칙을 정규식으로 어디까지 강제할 수 있는지 먼저 정한다.** 「아픔으로 시작하는가」는
> 정규식이 판정할 수 없다. 강제할 수 있는 것은 **금지 패턴**(기능·무료·브랜드명으로 시작,

> 나눠 적는다 — 「규칙이 있다」와 「규칙이 강제된다」가 같아 보이면 안 된다(S7 부터의 관례).

## (c) Shorts — 1080×1920, 30초, 번인 자막

마케팅 계획 §1 구조:

```
0~5초    문제(아픔) 카드 1문장 — 큰 글씨
5~10초   왜 그런가 카드 또는 실패 장면
10~25초  해결 — 실제 화면 녹화(세로), 자막 3줄
25~30초  결과 한 줄 + 랜딩 URL 카드
```

- 출력: `content/jp/epNN/shorts.mp4` + `shorts_title_ja.txt` + `shorts_desc_ja.txt`
- **자막은 번인(burn-in)**. 소프트 자막 금지 — Shorts 는 음소거 재생이 기본이고 플랫폼이
  소프트 자막을 항상 보여주지 않는다.
- 트랙 B 는 해결 장면 대신 **비교 카드 3장 전환**(마케팅 계획 §1).
- 제목 JA 질문형 20자 내 + 해시태그 3, 설명란 끝에 블로그 URL(`?via=youtube&ep=NN`).
- 검증: **길이 ≤30초 · 해상도 정확히 1080×1920** 을 파일에서 다시 읽어 확인(ffprobe).
  레이아웃한 값이 아니라 **파일의 값**을 본다(guide PDF 페이지 수와 같은 이유).

> ⚠️ 기존 `demo.gif`(가로 720×1280 녹화)는 **그대로 둔다** — X 용이고 포맷이 다르다.
> 세로 녹화는 Shorts 전용으로 따로 찍는다.
