# SafeFile JP 접촉 로그

파일럿 접촉(메일·전화·대면) 이력의 **단일 정본**이다. 신청 자체는
`/admin/jp_pilot_requests`(DB `jp_pilot_requests`)에 남지만, 그 뒤에 일어난 일 —
회신했는지, 무엇을 요구했는지, 결제까지 갔는지 — 은 코드가 알 수 없으므로 여기에 손으로 적는다.

> 왜 DB 가 아니라 git 인가: 이 표의 값은 판단이다("회신 = 거절", "파일럿 = 보류").
> 판단은 바뀌고, 바뀐 이력이 남아야 예측 채점(`jp_forecast_report_2026-10-22.md` §7)이
> 사후 합리화가 아니라는 것을 보일 수 있다. git 이 그 이력을 공짜로 준다.

## 기재 규칙

- **업체 유형**: `建設業` / `電子入札代行` / `行政書士` / `その他`
  (`jp_pilot_requests.industry` 와 같은 네 가지. 다른 말을 쓰면 집계가 갈라진다)
- **발주처**: 상대가 알려준 발주처명 1곳. 안 알려줬으면 `—`
- **회신**: `無` / `拒否` / `質問` / `承諾` — 없으면 `無`(공백 아님. 공백은 "아직 안 물어봤다"와
  구별되지 않는다)
- **파일럿**: `申込` / `開始` / `離脱` / `—`
- **결제**: `—` / `月額` / `年額` / `30日パス`
- **메모**: 다음 행동 하나. 날짜 없는 "검토 중" 은 쓰지 않는다 —
  **시간 약속은 하지 않지만, 무엇을 기다리는지는 적는다.**

개인 이름·연락처는 **여기에 적지 않는다.** 그것은 `jp_pilot_requests` 에만 있고,
랜딩의 동의 문구(「ご連絡のためにのみ使用します」)가 덮는 범위도 거기까지다.
공개 저장소이므로(`chaop2026/docpack` 은 PUBLIC) 업체명도 식별 가능하면 적지 않고
`A社`·`B社` 로 적는다.
