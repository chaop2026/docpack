## 2. (a) utm 폐기 — 차단당하는 계측은 계측이 아니다

**증상**: Justin 의 Chrome(차단 확장)에서 `?utm_*` 이 붙은 주소가 열리지 않는다.
**서버는 전부 200 을 돌려주고 있었다** — 서버 쪽에서는 보이지 않는 고장이고, 그 방문들은
「출처 없음」으로 세어지고 있었다.

바꾼 곳: `jp_episode_source#via_url`·`blog_url` · `make_episode viaUrl` · `_jp_article` CTA ·
`jp.js` · `SafeEvent` · `JpWeeklyKpi` · 콘텐츠 3편(재빌드) · 손으로 쓴 `linkedin_en.md`·`summary_ko.md`.

### 설계 결정 셋

1. **`utm_source` 키를 지우지 않았다.** 이미 저장된 행이 있고, 밖에 나간 옛 링크(블로그 본문·
   10-24 이전 트윗)가 계속 그 파라미터로 도착한다. 지우면 그 방문이 `none` 으로 떨어져
   **「유입이 줄었다」로 보이는데 실제로는 측정을 그만둔 것**이다. KPI 가 두 차원을 합산하고,
   주간 표는 **두 열로 나눠** 보여준다 — `utm_source` 열이 0이 되는 것이 전환 완료의 유일한 신호다.
2. **`ep` 는 새 차원이다.** `utm_campaign` 은 URL 에만 있고 **저장된 적이 없다**(`KEYS` 밖).
   회차별 유입을 처음으로 볼 수 있게 됐다. 고정 목록(`ep01`~`ep33` + `other`).
3. **`medium` 은 삭제.** `social|organic` 뿐이었고 채널에서 파생되며 저장된 적도 없다 —
   아무도 읽지 않는 파라미터는 틀릴 수만 있다.

### 🔴 P16 의 분모를 고쳤다 (내가 만들 뻔한 결함)

`jp.js` 가 직접 방문에서 키를 **생략**하도록 바꿨다(`via:'none'` 과 `utm_source:'none'` 을
동시에 보내면 같은 비사실을 두 열에 쓴다). 그런데 `landing_views_by` 는 **null 그룹을 버린다.**
그대로 두면 `by_source.values.sum` 이 분모가 되어 **분모가 조용히 「출처가 있던 방문」**이 되고,
직접 유입이 늘수록 P16 이 100% 에 수렴한다.

→ 분모는 `landing_view` **전체**를 센다. 실측(개발 DB): 전체 187 / 출처 기록 136.
전용 테스트가 이 구별을 고정한다.

## 3. (b) 「아픔으로 쓰였는가」는 정규식이 판정할 수 없다

판정할 수 있는 것은 **아픔일 수 없는 형태**뿐이다 — 통계·해설 도입(`~の多くは` / `~が原因です`),
브랜드명·기능·「無料」·퀴즈형 시작, 그리고 길이. 강제되는 것과 사람이 읽는 것을 나눠 적는
기존 관례를 따랐다(전략 §3-3 비고란에 명시).

**길이 40자는 지표이지 상한이 아니다.** 아픔의 한 줄은 짧고, 길어지는 것은 해설을 시작했다는
뜻이다. 실측: 개정 전 ep01 hook 은 **43자**이고 통계 틀 + 결론 설명으로 **2건 위반**.
재작성한 셋은 27·35·33자, 전부 clean — **규칙이 실제로 기존 문안을 잡는다는 증거.**

| | 전 | 후 |
|---|---|---|
| ep01 | 入札書類の差し戻しの**多くは**…が**原因です**。(43자, 2위반) | 黒塗りが一箇所だけ残っていて、入札書類が差し戻された。(27자) |
| ep02 | 入札公告の「マスキングのうえ提出」は、どこを隠すかを書いていないことがあります。 | 「マスキングのうえ提出」とだけ書いてあって、どこを隠すのか分からない。(35자) |
| ep03 | AIに契約書の意味を聞くとき、相手方の氏名と口座番号まで一緒に送っています。 | 契約書をAIに貼った後で、相手方の口座番号も送っていたと気づいた。(33자) |

`x_thread.md` 는 생성물이므로 **`post_ja.md` 의 `hook` 을 고쳐 재빌드**했다(직접 고치면 다음
빌드가 되돌린다).

### ⚠️ ep05·ep06 의 「근거 미확인」을 닫았다 — 추측이 아니라 원문을 읽어서

S7 보고서가 「본문 전에 공고 1건 확인」으로 남긴 두 항목이다. 지시서는 ①출처 확보 /

**ep05** — 국토교통성 관동지방정비국 「입찰설명서(공통사항) 令和8年4月1日時点」, PDF 직접 읽음(HTTP 200):
> 「申請書類は、全てを一つのファイルにまとめ（２つ以上のファイルは認めない。…）…**ファイル容量の合計は 10ＭＢ以内**に収め」
> 「圧縮することにより 10ＭＢ以内に収まる場合は、ZIP 形式又は LZH 形式により圧縮（自己解凍形式は除く。）して送付することを認める」

읽어 보니 **원래 계획보다 좋은 기사**가 됐다. 상한이 **발주자마다 5MB / 10MB / 50MB 로 10배
차이**나고, 「2개 이상의 파일은 인정하지 않는다」가 함께 적힌다. 그래서 기사의 주장이
「상한은 N MB 다」가 아니라 **「순서를 바꿔라 — 검은 칠 먼저, 용량 확인 마지막」**이 됐다.

> ⚠️ **topics.json 의 ep05 제목이 「一度に片づける」였다.** 「一括」 은 금지어지만 「一度に」 는
> 아니다 — 가드는 통과한다. 그래도 **복수 파일을 한 번에 처리한다는 오해**를 부르는 문구라,
> 본문에 「여러 서류를 1개 파일로 합치는 작업은 제출요령이 시키는 것이고 **이 도구가 하는 일이
> 아니다**」를 명시하고 기사 제목은 「容量制限と黒塗りの順番」으로 바꿨다. 미출시 기능을
> 광고하지 않는다는 규칙은 가드가 잡는 단어보다 넓다.

**ep06** — 경제산업성 「보조사업 사무처리 매뉴얼」(49쪽), PDF 직접 읽음(HTTP 200):
> 「⑧ 個人情報保護の観点から必要がある場合は、**適宜マスキング等の処理をしてください**。」

범위가 제시되지 않는다 — ep02(입찰 공고)와 **같은 구조**이고 기사도 그렇게 연결한다.
「마이넘버 기재 부분을 마스킹」이라고 구체적으로 쓰는 수첩도 있지만 **검색 스니펫으로만 봤으므로
본문에서 출처로 달지 않고** 「사업 유형에 따라 구체적으로 쓰는 수첩도 있다」 수준으로만 언급했다.

### 🔴 가드가 ep08 을 잡았고, 가드가 옳았다

`legal_claim` 의 `required` 패턴(`(が|を)求められ(て|ます|る|た)`)이 세 문장에서 발화했다 —

요구한다**는 뜻이지 법이 요구한다는 뜻이 아니다.

**가드를 느슨하게 하지 않고 문장을 고쳤다**(「用意する」「必要になる」). S8 에서 ep03 이
출처 대신 문장을 고친 것과 같은 판단이다 — 규칙의 자기 주석이 「오탐은 저자가 필요 없는 문장에
인용을 붙이게 만든다」고 경고하고 있고, 여기서는 **바꾼 쪽이 더 정확한 일본어**였다.
