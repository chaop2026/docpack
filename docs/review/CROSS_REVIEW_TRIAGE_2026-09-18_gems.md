### a-1. `canonical_sweep.rb` 는 sitemap 이 죽으면 **0건 검사하고 통과한다** (확신도 높음)

**Codex 의 말**: `script/canonical_sweep.rb:83-85` 가 `/sitemap.xml` 의 응답 코드도 `<loc>`
개수도 단언하지 않고 body 만 파싱한다. `SLUGS` 가 비면 `[3/6]`·`[4/6]` 이 0회 돌고 숫자만 찍는다.

**재현 — 그대로다.** `SLUGS` 산출부만 `[]` 로 바꾼 사본을 **실제 앱에** 겨눴다:

```
sitemap entries: 0
[3/6] sitemap …            0 entries checked
[4/6] internal links …     0 distinct internal link targets checked
============================================================
ALL CHECKS PASSED
```

**이 저장소가 반복해 당한 바로 그 모양이다** — "0 tests" 가 통과처럼 보였던 minitest 사고와
같은 형태이고, 그 교훈을 적어놓은 저장소에서 내가 같은 것을 다시 만들었다.
게다가 **하필 `[3]`·`[4]` 는 sitemap 이 정상일 때만 의미가 있는 검사**라, sitemap 렌더가 깨지는
순간 — 즉 가장 확인이 필요한 순간 — 조용해진다.

| 항목 | 내용 |
|---|---|
| 위험도 | **AMBER** — 앱은 멀쩡하지만 **안전망이 소리 없이 꺼진다** |
| 수정 방향 | `SLUGS` 산출 직후 ① `/sitemap.xml` 이 200 인지 ② `<loc>` 가 **1개 이상**인지 단언하고, 없으면 즉시 `fail!` + exit 1. 나아가 **하한 개수**(예: 로컬 DB 기준 최소 5)를 두면 "sitemap 이 절반만 렌더됐다" 도 잡힌다 |
| 언제 | 다음 런. **배포를 막지 않는다** (스크립트는 개발자 도구이지 런타임이 아니다) |

### a-2. `[5/6]` JSON-LD 비교는 **단언 0회로도 통과한다** (확신도 높음)

**Codex 의 말**: `:182-192` 가 `u.include?("/blog/")` 인 값만 비교한다. JSON-LD 블록이 사라지거나
URL 필드가 없어지면 실패가 0건이고, `:204` 의 "pages checked" 는 **페이지 수**이지 비교 수가 아니다.

**재현 — 지금은 공허하지 않지만, 공허해지는 것을 막는 장치가 없다.** 비교 횟수를 세어봤다:

```
[5/6] canonical vs JSON-LD url/@id, hreflang sanity
  31 pages checked | JSON-LD comparisons actually executed: 6
```

6 = 글 3개 × 필드 2개(`url`, `@id`). 즉 **오늘은 실제로 검사한다.** 문제는 이 검사가 존재하는
이유가 *"JSON-LD `url` 이 canonical 과 어긋났다"*(2026-09-18 A1) 였다는 점이다 — 그 블록이
통째로 사라지는 회귀가 오면 이 검사는 **"31 pages checked" 를 찍고 통과한다.**
내가 패키지 Q6 에서 스스로 의심했고, Codex 가 같은 결론을 냈다.

| 항목 | 내용 |
|---|---|
| 위험도 | **AMBER** — a-1 과 같은 종류 |
| 수정 방향 | 비교 횟수를 세고 **0이면 실패**. 출력에도 페이지 수가 아니라 **비교 수**를 찍는다. 같은 규칙을 `[6/6]` 의 hreflang 루프에도 적용할지 함께 본다 |
| 언제 | 다음 런 |

### a-3. `middleware_probe.sh` 의 임시 이니셜라이저가 남으면 **정적 서빙이 통째로 꺼진다** (확신도 높음 — Codex 는 "보통")

**Codex 의 말**: `script/middleware_probe.sh:14-16` 이 `config/initializers/aaa_static_probe.rb` 를
`trap EXIT` 로만 지운다. `trap EXIT` 는 SIGKILL 을 처리하지 못한다.

**재현 — 맞다. 그리고 Codex 가 말한 것보다 나쁘다.**

측정 ①(결과): 그 파일이 있는 상태에서 **프로덕션 스택**을 뽑으면

```
ActionDispatch::Static count: 0
```

정적 서빙 미들웨어가 **스택에서 사라진다**. 프로덕션은 `RAILS_SERVE_STATIC_FILES=true` 로
`public/` 을 자기가 서빙하므로, `/safe/`·`/privacy/`·`/assets/*` 가 전부 죽는다.
"초기화 옵션이 하나 달라진다" 가 아니라 **사이트가 깨진다**.

측정 ②(잔존 경로): `trap EXIT` 는 SIGTERM 에는 돌지만 SIGKILL 에는 안 돈다 —

```
--- SIGKILL ---   파일 잔존 (trap EXIT 안 돎)
--- SIGTERM ---   제거됨 (trap EXIT 돎)
```

그리고 **더 현실적인 경로가 따로 있다**: 이 스크립트는 컨테이너 안에서 돌고 저장소는
바인드 마운트다. 실행 중에 `docker compose restart web` 이 들어오면 프로세스는 죽고 **파일은
호스트 트리에 남는다.** 실측:

```
프로브 파일 생성됨
컨테이너 재시작 후에도 파일 잔존 — 바인드 마운트라 호스트 트리에 남는다
```

⚠️ **나는 이번 세션에 `docker compose restart web` 을 열 번 넘게 돌렸다.** 가설이 아니다.

측정 ③(안 잡히는가): 그 파일은 gitignore 되지 않아 `git status` 에 `??` 로 뜬다 — 즉
"사람이 보면 안다". 그런데 **이번 세션에서 내가 `git add -A` 로 의도치 않은 심링크를
커밋에 쓸어 담았다**(커밋 `4888bfd` → `8b5…` 에서 되돌림). 그 안전망은 실제로 뚫렸다.

| 항목 | 내용 |
|---|---|
| 위험도 | **AMBER (배포 위험)** — 이 파일이 커밋에 섞여 배포되면 사이트가 깨진다 |
| 수정 방향 | ① 프로브 파일명을 `.gitignore` 에 넣어 **커밋 자체가 불가능**하게 한다(가드보다 강한 것은 "존재할 수 없음") ② `trap EXIT` 외에 스크립트 **시작 시점에도** 잔존 파일을 지운다 ③ 더 나은 방향: 이니셜라이저를 만들지 말고 **환경변수로 분기**하게 `canonical_path_redirect.rb` 를 바꾸거나, 프로브를 컨테이너 밖 임시 복사본 트리에서 돌린다. 어느 쪽이든 **"파일을 저장소 안에 잠깐 만든다" 자체를 없애는 것**이 맞다 |
| 언제 | 다음 런. **배포 전 처리 권장** — 지금 트리에는 없다(확인함: `config/initializers/` 에 프로브 파일 없음) |

- 상한은 **오늘 당장 minitest 7 이 나와도 막는다.** CI 단언은 minitest 7 이 들어온 **뒤에**
  빨간불을 켠다. 순서가 다르다 — 상한은 예방, 단언은 탐지다.

  주석에만** 적었고, 주석은 실행되지 않는다.
- 그래서 **둘 다** 가 답이다: 상한 유지 + `bin/rails test <file>:<line>` 이 1건만 도는지
  단언하는 테스트. 후자는 *새 테스트를 짜는 일*이라 젬 업그레이드 런에 섞지 않는다.
