## 항목 1 (RED) — `/safe/` 가 거짓 약속을 하고 있었다

### 무엇이 거짓이었나

`public/privacy/index.html` §3-1 은 KO·JA 양쪽에서
「파일을 열어 처리하는 화면(`/safe/`)에서는 접속 분석도, **제3자 스크립트도** 사용하지
않습니다」라고 약속한다. 그 페이지는 실제로 **5개**를 외부에서 받고 있었다 —
cdnjs 4개(`pdf.min.js`·`pdf.worker.min.js`·`mammoth.browser.min.js`·`jspdf.umd.min.js`)와
jsdelivr 1개(`heic2any.min.js`).

파일이 밖으로 나가지는 않지만, 신분증을 여는 화면에서 저 문장이 틀리면 **그 페이지의
다른 약속도 확인할 수 없는 말**이 된다. 제3자 스크립트의 쿠키·네트워크 호출은 제출하는
사람이 결과 파일만 보고 감사할 수 없다 — S11b 가 AdSense 를 지울 때 쓴 바로 그 근거다.

### 고친 방법 — 문장이 아니라 파일을 옮겼다

`public/safe/vendor/` 에 **같은 버전**을 둔다(전송 경로 변경이지 업그레이드가 아니다).
부수 효과로 cdnjs 장애가 더는 도구를 멈추지 않는다.

**바이트 출처를 독립 대조했다.** 받은 파일을 다시 해시하면 자기 자신과 항상 일치하므로
검사가 아니다. 그래서 *다른 응답*과 비교했다:

| 파일 | 대조 대상 | 결과 |
|---|---|---|
| `pdf.min.js` | cdnjs API `sri` (pdf.js 3.11.174) | sha512 일치 |
| `pdf.worker.min.js` | 동일 | sha512 일치 |
| `mammoth.browser.min.js` | cdnjs API `sri` (mammoth 1.6.0) | sha512 일치 |
| `jspdf.umd.min.js` | cdnjs API `sri` (jspdf 2.5.1) | sha512 일치 |
| `heic2any.min.js` | npm 0.0.4 tarball 내부 `package/dist/…` | sha256 동일 |

`SHA256SUMS`(`shasum -a 256 -c` 로 바로 검증 가능) + 라이선스 4종(Apache-2.0 / BSD-2 /
MIT / MIT) 동봉. 권한 644, 디렉터리 755 — `public_assets_readable_test` 통과.

### 📌 범위 이탈 ① — heic2any 도 같이 옮겼다 (지시는 4개)

지시서는 cdnjs 4개만 지정했다. heic2any 를 추가한 이유: **단일 파일·설정 0·위험 0**의
같은 성격의 변경이고, 이것을 빼면 거짓 표면이 「두 라이브러리」로 남는데 넣으면 「하나」가
된다. 1.35MB.

### 📌 범위 이탈 ② — Tesseract 는 옮기지 않았고, 그래서 문장을 손댔다

**지시서의 전제가 불완전했다.** 교차검증도 cdnjs 4개만 셌다 — Tesseract 와 heic2any 는
JS 문자열 리터럴에서 지연 로드되므로 `<script src>` 스캔에 보이지 않는다.

Tesseract 를 옮기지 않은 근거(추정이 아니라 측정):

* 코어를 **런타임에 고른다** — v5 는 simd/lstm 변종 중에서 고르고, 그 래퍼 하나가 4.7MB.
* 그 뒤에도 **언어 데이터가 제3자에 남는다** — `kor.traineddata.gz` 단독 **7MB**(실측),
  페이지는 UI 언어에 따라 `kor+eng`/`eng`/`jpn+eng`/`spa+eng` 를 필요로 하므로 ≈20MB 이고
  인식 시점에 `tessdata.projectnaptha.com` 에서 받는다.

스크립트만 가져오면 **저장소를 읽는 사람에게는 닫힌 것처럼 보이고 네트워크 탭을 보는
사람에게는 열린 채**다. 그게 RED 가 지목한 실패 모양 그 자체라, 「약속을 더 그럴듯하게
만드는 변경」은 하지 않았다.

→ 지시서는 「문장은 이제 참이 되므로 유지」라고 했지만 **참이 되지 않는다.** 그래서
문장을 유지하되(기존 테스트·지시 모두 충족) **그 다음에 예외를 호스트명까지 명시**했다.
KO·JA 양쪽, 「외부에서 가져오는 것은 두 가지뿐입니다」+ OCR CDN 2곳 + 웹폰트 1곳.
**독자가 자기 네트워크 탭에서 확인할 수 있는 예외가, 확인할 수 없는 약속보다 낫다.**

웹폰트(`fonts.googleapis.com`)는 스크립트가 아니므로 §3-1 문장을 거짓으로 만들지는
않지만, 같은 이유로 함께 적었다. **다음에 들여올 것은 이것이다.**

### 테스트 — allowlist 를 비우고, 안 보이는 절반을 따로 봤다

* `/safe/ loads NO external script at all` — 외부 `<script src>` **0개**. allowlist 비었다.
* 같은 테스트의 둘째 절 — `PDF_WORKER`·`CDN_*` **상수 4개**를 소스에서 긁어 같은 출처인지
  본다. 이게 핵심이다: **jsPDF·heic2any 는 옛 allowlist 에 아예 없었다** — HTML 스캔에
  안 보이는 자리에 살았기 때문이다. 외부 호스트 집합이 `["cdn.jsdelivr.net"]` 과
  **집합 동등**이어야 하므로 두 번째 외부 라이브러리가 조용히 합류할 수 없다.
  상수를 4개 미만 찾으면 「아무것도 검사하지 않았다」로 **실패**한다.
* `every vendored library is actually served, and whole` — 5개 전부 200 + **SHA256SUMS 대조**.
  편집·절단·교체를 잡는다. 라이선스 4개 존재도 본다.
* `the service worker knows the libraries moved on-origin` — sw.js 에 cdnjs 가 없음 +
  precache 경로 전부 실제 200(OPTIONAL 자산의 오타는 **증상 없이** 오프라인 파이프라인을
  잃게 한다).

### 서비스 워커

`CACHE_VERSION` v2→v3 (죽은 cdnjs 런타임 엔트리 축출) · `CACHEABLE_CDN` 에서 cdnjs 제거
(페이지가 접촉하지 않는 호스트를 남기면 없는 의존을 주장하는 주석이 된다) ·
벤더 4개를 `OPTIONAL_SHELL_ASSETS` 에 추가(2.41MB).

**heic2any 는 일부러 precache 하지 않았다** — HEIC 전용 소수 경로인데 단일 최대 파일이라,
넣으면 페이지를 그냥 읽는 모든 사람에게 1.35MB 를 과금한다. 첫 사용 시 same-origin
cache-first 분기가 캐시한다 — CDN 에 있던 동안과 **같은 대우**다.

## 항목 2 (AMBER) — 브레드크럼이 남의 간행물을 부모라고 했다

S11 은 트레일을 **canonical 접두사**에 맞췄다. 그래서 `body_en` 이 있는 JP 회차가
`/en/blog/:slug` 에서 `Home → /en`, `Blog → /en/blog` 를 가리켰다.

`PostsController#index` 는 목록을 **트랙으로** 좁힌다 — `/ja/blog` 는 `Post.jp`,
`/blog`·`/en/blog`·`/es/blog` 는 한국어 글. 즉 **`/en/blog` 는 이 글을 담지 않고 앞으로도
담지 않는 다른 간행물**이고, 브레드크럼은 문서가 사이트에서 어디 앉아 있는지에 대한
주장이므로 그 주장이 거짓이었다.

→ 두 단 모두 **`/ja` 로 고정**. 접두사를 섞는 쪽(Home=/en, Blog=/ja/blog)이 더 나쁘다 —
어디에도 없는 계층을 묘사한다. **라벨은 페이지 언어를 따른다**(영어 글은 "Home › Blog") —
이름은 독자에 대한 배려이고 URL 은 사실 주장이며, 사이트와 맞아야 하는 건 둘째뿐이다.
JSON-LD 와 **가시 트레일을 같은 커밋에서** 바꿨다(링크를 누르는 독자가 가장 먼저 안다).

**전제를 산문이 아니라 측정으로 테스트에 넣었다**: `/en/blog` 는 이 글을 싣지 않고
`/ja/blog` 는 싣는다를 실제 HTTP 로 단언한다. 이게 이 수정이 옳은 이유 전부다.

한국어 트랙 42개 글 마크업 **불변** — E-1 38행 대조 통과, 스냅샷 파일 미수정.

## 항목 3 (AMBER) — 키가 틀려도 「성공처럼」 제출됐다

`IndexNow.key` 는 non-blank 만 봤고, 키 파일 라우트는
`/[A-Za-z0-9][A-Za-z0-9_-]{7,127}\.txt/` 로 제약돼 있다. 그 사이의 값 — here-doc 의 후행
개행, 남은 따옴표, 8자 미만 — 은 **제출은 되고 `keyLocation` 은 404** 를 가리켰다.

**증상이 없는 것이 핵심이다**: IndexNow 는 `202`(「키 미검증」)를 주고, 그건 **정상적인
첫 제출과 똑같은 응답**이다. 로그에 「거부」라고 적히는 곳이 없다.

→ `KEY_FORMAT` 이 **라우트 정규식과 글자 단위로 같다**(사양이 아니라 라우트를 맞춘 이유:
파일을 서빙할 수 있는지 결정하는 건 라우트다). 불일치는 **드라이런** — 기록되는 상태이고
주간 보고서가 출력한다. 경고 1줄, **값 없이 길이만**, 값별 1회(`submit` 한 번이 `key` 를
다섯 번 부른다 — 같은 줄 다섯 개는 문제 다섯 개로 읽힌다).

테스트 7가지 실패 모양(후행 개행·따옴표·내부 공백·선행 공백·7자·선행 하이픈·금지 문자)
+ **정상 32hex 가 받아들여지고 라우트가 실제로 서빙하는지**(이게 없으면 위 전부가
「`key` 가 항상 nil」일 때도 통과한다) + 8/128/129 경계.

## 부수로 고친 것 — SW 하네스가 오진하고 있었다

`test/sw/offline_resilience.mjs` 가 캐시 이름을 `'safefile-shell-v2-'` 로 **박아뒀다**.
`CACHE_VERSION` 범프는 그 상수의 존재 이유인데, 범프하자 **서비스 워커가 멀쩡한 상태로**
5건이 빨개졌다. 게다가 이름이 틀렸다 — 없는 키 조회는 `undefined` 라, **제 이름으로 존재하는
캐시에 대해 「FAIL v1 shell cache exists」**를 찍는다. 엉뚱한 걸 탓하는 빨간 하네스는
「버전을 범프하지 않는」 방식으로 고쳐진다.

→ `sw.js` 에서 읽는다. 읽지 못하면 **결과를 보고하지 않고 중단**(exit 2) — 대안은 모든 캐시
이름을 `undefined` 와 비교하는 것이고, 그게 하네스가 아무것도 검사하지 않고 통과하거나
실패하는 방식이다. 변이 프로브로 중단 경로까지 확인했다.

**B-1. 「제3자 스크립트 없음」 문장의 최종 문안 (KO·JA)**
지시서는 문장을 그대로 두라고 했지만 Tesseract·웹폰트 때문에 그대로는 **거짓**이다.
내 판단으로 문장을 유지하고 **예외를 명시**했다(위 범위 이탈 ②). 대안은 셋이고,
어느 쪽이든 한 문단 편집이다:
 (a) 지금대로 — 절대문 + 명시된 예외 2개 ← 현재 커밋
 (b) 절대문을 버리고 「분석·광고 스크립트는 없고, 처리 라이브러리는 자체 제공, 외부는
     OCR 과 글꼴뿐」으로 서술형 재작성
 (c) Tesseract 코어까지 자체 호스팅(≈4.9MB 커밋) — 그래도 언어 데이터 20MB 는 외부로
     남으므로 **예외 문장은 여전히 필요하다**. 비용 대비 얻는 게 가장 적다.
