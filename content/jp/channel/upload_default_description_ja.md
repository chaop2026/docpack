# 長い動画の説明欄（月1本・3〜5分のガイド）

**2026-11-16 に用途を変更した。** v2 ではショート動画の説明欄の雛形だったが、
ショートの説明欄のリンクは**押せない**。押せる面に移した。

このファイルは**雛形そのもの**で、`scripts/content/make_longform.mjs` が読んで
置換する。人が手で貼るときも同じものを使う — 機械と人で別の雛形を持つと、
片方だけが直って**どちらが本物か分からなくなる。**

## 置換される印

| 印 | 何に変わるか |
|---|---|
| `{{MONTH}}` | 対象月（`2026-11`） |
| `{{HOOK}}` | その月の先頭回の痛み1行（`post_ja.md` の `hook`） |
| `{{LANDING}}` | ランディングの URL（`?via=yt_long`・**`ep` なし**） |
| `{{CHAPTERS}}` | 目次（`00:00 …` の行が回数分） |
| `{{ARTICLES}}` | その月の記事リンク（1行1本・各回の `ep` 付き） |

---

```
{{HOOK}}
→ ブラウザだけで試す: {{LANDING}}

この動画は {{MONTH}} に公開したショート動画をひとつの手順としてまとめたものです。
書類ごとに「隠すところ」と「残すところ」を分けて説明します。

{{CHAPTERS}}

くわしい手順（日本語の記事）
{{ARTICLES}}

このツールはファイルをサーバーに送りません。処理はブラウザの中だけで終わります。
AIによる深いスキャンを使うときだけ、抽出したテキストがサーバーに送られます。

隠す範囲は提出先によって異なります。
提出先の指示を必ず確認してください。

#黒塗り #個人情報 #提出書類
```

## 🔴 最初の2行がすべて

3行目から**折りたたまれる**。折りたたみの下のリンクは、事実上ないリンクだ。
だから1行目=痛み1行、2行目=ランディングのリンク。目次もタイトルも、その後。

## `?via=yt_long` を使う理由

ショート（`via=youtube`）と**同じ値にしない**。長い動画は「もう1本見た人」が来る面で、
ショートは「初めて見た人」が来る面だ。同じ値にすると、どちらが効いているのか
**二度と分けられない**（過去のイベント行は後から分類できない）。

⚠️ `yt_long` は `app/models/safe_event.rb` の `VALUES["via"]` と
`public/safe/jp/jp.js` の `VIA_CHANNELS` の**両方**にある。片方だけだと、
サーバーが**イベント全体を破棄**し、`sendBeacon` は応答を読まないので
**両側から見えない**。集合が一致することをテストが固定している。

## 🔴 `{{LANDING}}` に `ep` が付かない理由

この動画は**4回分**をまとめたもので、どれか1回ではない。`ep=ep05` を付ければ
その回を見て来たことになるが、実際には月のまとめを見て来ている。
だから本体の CTA は `?via=yt_long`（`ep` なし）で、**記事リンクのほうだけ**が
各回の `ep` を持つ。

集計ではこう読める:

| 形 | 意味 |
|---|---|
| `via=yt_long`（ep なし） | 長い動画の本体 CTA から |
| `via=yt_long&ep=epNN` | 長い動画の中の、その回の記事リンクから |

## 貼る前の確認

- [ ] `{{` が**ひとつも残っていない**
- [ ] 1行目が痛み・2行目がリンク
- [ ] リンクの `via` が **`yt_long`**（`youtube` ではない）
- [ ] 必須文が独立行で入っている
- [ ] 目次の秒数が**実際の動画**と合っている（ズレた目次は押すと別の場所に飛ぶ）
