## 0. 🔴🔴 시작하자마자 — 잠금 파일을 잡는다

```
printf 'HELD %s night_run\n' "$(date '+%Y-%m-%d %H:%M:%S')" > logs/night/RUN.lock
```
그리고 **끝날 때(실패해도)**:
```
printf 'RELEASED %s night_run\n' "$(date '+%Y-%m-%d %H:%M:%S')" > logs/night/RUN.lock
```

🔴 **파일을 지우지 않는다 — 덮어쓴다.** 파일은 **하나만** 유지한다.
지우는 방식이었을 때는 런이 죽으면 lock 이 남아 다음 런을 영원히 막았고, 그걸
풀려면 **사람이 파일을 지워야** 했다 — 이 저장소의 삭제 안전 정책 아래에서
에이전트는 지울 수 없다. `RELEASED` 를 쓰는 방식은 **죽어도 내용이 남아** 무슨
일이 있었는지 보인다.

⚠️ 런처(`scripts/night_run.sh`)도 `trap` 으로 같은 줄을 쓴다. 중복이 아니라
**그물이 둘**이다 — 네가 죽은 날은 네가 쓰는 줄까지 가지 못한다.

## 0-1. 🔴🔴 「Justin 요청」이 있는 카드를 가장 먼저 집는다

보드 속성 **`Justin 요청`**(텍스트) 과 **`요청 처리`**(선택: 새 요청 / 반영 중 /
반영됨 / 허브로 넘김).

1. `Justin 요청` 이 **비어 있지 않고** `요청 처리` 가 **비었거나 「새 요청」** 인
   카드를 **먼저** 집는다. 다른 모든 일보다 앞이다.
2. `요청 처리` → **「반영 중」** 으로 바꾼다.
3. **그 회차만** 고친다. 🔴 **겸사겸사 다른 회차를 건드리지 않는다.**
4. 끝나면 **「반영됨」** + 카드 본문에 한 줄:
   `[요청 반영 YYYY-MM-DD] 무엇을 바꿨나`
5. 검수로 보낸다(단계 → 「검수」).

### 🔴 카드 하나로 끝나지 않는 요청은 **고치지 않는다**

새 컨셉 · 규칙 변경 · 새 채널 · **비용이 늘어나는 일** · **전 회차 일괄 변경** —
이런 요청은 **「허브로 넘김」** 으로 두고 본문에 **왜 넘겼는지 한 줄**을 적는다.
무인 런이 규칙을 바꾸면 **아무도 그 결정을 내린 적이 없는데 규칙이 바뀐다.**

🔴 **사람이 쓴 요청 문구는 지우지 않는다.** 상태만 바꾸고 본문에 덧붙인다.

## 할 일

(🔴 위 0-1 의 「Justin 요청」 카드를 **다 처리한 뒤에** 여기로 온다.)

1. 보드에서 대상 카드를 고른다. 조건:
   - `게시 예정` 이 **다가오는 토요일 승인 + 7일 안**(= 아직 게시 안 된 지난
     카드 포함). 토요일 승인은 **그 주의 월요일 가이드 + 목요일 사건** 게시분을
     한 번에 본다 — 「이번 주」만 집으면 그 카드들은 **게시 당일 밤**에야
     만들어져 승인이 게시보다 늦는다.
   - `단계` ∈ {**콘티**, **제작**, **썸네일**, **반려**} · `승인` 미체크
   - 게시일이 **가까운 카드부터** 처리한다
   🆕 **「반려」 카드도 집는다.** 반려는 끝이 아니라 **되돌아온 일감**이다.
   반려만 쌓이고 아무도 집지 않으면 검수는 쓰레기통이 된다.

2. 카드마다 순서대로. 🔴 **썸네일이 쇼츠 렌더보다 먼저다** —
   `make_short.mjs` 가 `short_ja.json` 의 `cover` 로 지정된 `thumb_short_*.png`
   를 **끝 화면(29.5~30.0초)** 에 넣는다. 썸네일이 없으면 끝 화면이 마감 카드로
   조용히 떨어지고, 그 사실은 `short_ja.json` 의
   `end_card.fell_back_to_closing_card` 에만 남는다.

   - **video-story** — 회차에 `post_ja.md` 가 없을 때만. hook 3안과 쇼츠 대본.
     🔴 `content/jp/topics.json` 을 **직접 고치지 않는다**(제안만). `ep` 는 발행
     순서이자 폴더 이름이자 계측 차원(`?ep=epNN`)이라, 바꾸면 **이미 게시된
     링크가 다른 회차를 가리킨다.**
   - **video-thumbnail** — `content/jp/epNN/thumb_ja.json` 을 쓰고
     ```
     node scripts/content/make_thumbnail.mjs NN --only=short
     ```
     틀은 `intent` 가 정한다(理由→warn · 手順→steps · 比較→versus). **고르지 않는다.**
     🔴 `focus: true` 는 `masked: true` 인 행에서만 보인다.
   - **video-production** — 쇼츠를 끝 화면이 든 버전으로 렌더한다:
     ```
     node scripts/content/make_short.mjs NN
     ```
     🔴 **`make_episode.mjs` 를 돌리지 않는다.** 2026-11-05 에 그것을 ep01~08 에
     루프로 돌려 **산출물 45개를 퇴화시켰다**(guide PDF 가 실제 스크린샷을 잃었다).
     쇼츠만 다시 만들 때는 `make_short.mjs` 가 맞는 진입점이고, 그것은
     `manifest.json` 을 건드리지 않는다.
   - 가드를 통과시킨다:
     ```
     node scripts/content/qa_video.mjs NN
     ```
   - 단계를 올린다: 제작 → 썸네일 → **검수**

3. **반려 카드는 사유를 고치고 「검수」로 다시 올린다.**
   - `반려 사유` 를 읽고 **그 사유만** 고친다. 겸사겸사 다른 것을 바꾸지 않는다 —
     무엇이 고쳐졌는지 검수자가 알 수 없게 된다.
   - 고친 뒤 `반려 사유` 에 `[재작업 N회차] 고친 것: …` 을 **덧붙인다**(지우지 않는다).
   - 🔴 **같은 사유로 두 번째면 멈춘다.** 단계를 「반려」 그대로 두고 `반려 사유`
     앞에 **`사람 확인 필요:`** 를 붙인 뒤 다음 카드로 간다. 두 번 같은 자리에서
     막혔다는 것은 **고치는 법을 모른다는 뜻**이고, 세 번째 시도는 같은 결과에
     시간만 쓴다.
   - 🔴 **사람 몫은 고치지 않는다**: 채널 개설 · 업로드 · 예약 · 승인 체크 ·
     **새 이미지·영상 생성(과금)** · 사건편의 **귀 검수**. 이것들이 사유면
     **바로** `사람 확인 필요:` 를 붙인다.

4. 🔴 **검수는 하지 않는다.** 야간 런은 「검수」까지만 올리고 멈춘다 —
   검수는 **제작과 분리된 세션**에서 `video-qa` 로 돈다. 만든 사람이 자기 산출물을
   검사하면 「검사가 통과한 것」과 「대상이 올바른 것」을 구분하지 못한다.

5. 로그: `logs/night/YYYY-MM-DD.log` — 카드마다 **시작·끝·결과 한 줄**.

## 실패해도 멈추지 않는다

🔴 **한 카드가 실패하면 그 카드만 「반려」로 두고 다음 카드로 간다.**
실패 이유를 로그와 카드의 `반려 사유` 에 **한 줄**로 적는다.
런 전체를 중단하면 뒤 카드는 **아무도 모르게** 안 만들어진다.

## 🔴 돈이 드는 일 — 하지 않는다

**새 이미지·영상 생성은 하지 않는다.** 썸네일은 **앱 화면 캡처와 글자로만**
만든다(`scripts/content/templates/thumbnail/` 의 고정 틀). 생성 모델을 부르지
않는다. 과금이 필요한 카드는 **「반려 · 사유: 사람 확인 필요: 과금 필요」**.

## 🔴 하지 말 것

- **업로드하지 않는다. YouTube 예약·게시하지 않는다. 채널을 만들지 않는다.**
  공개·비공개·예약 전부. 그건 **허브(「SNS 계정 운영」 프로젝트)** 몫이고,
  필요하면 로그에 「허브에 요청: …」 한 줄로 남긴다.
- **승인 체크를 건드리지 않는다** — 승인은 사람이 토요일에 한다.
- 사건편의 **「사람 확인」 칸의 🔴 귀 검수 표시를 지우지 않는다.**
- 법적 문서·문의 메일을 건드리지 않는다. **일본 변호사 검토는 아직 없다.**
- `git push` 하지 않는다. 배포하지 않는다(이 저장소는 push 가 사람 몫이다).
- 커밋은 해도 되지만 🔴 **경로를 지정해서만** 한다:
  ```
  git add content/jp docs/autorun logs/night/*.log
  git commit -m "[night] 야간 런 YYYY-MM-DD"
  ```
  🔴 ~~`git add -A`~~ **금지.** 같은 저장소에서 사람이·다른 세션이 동시에 일한다 —
  `-A` 는 **남의 미완성 작업까지** 쓸어 담아 커밋한다. 2026-11-07 에 실제로
  의도치 않은 심링크가 커밋에 쓸려 들어간 적이 있다.
  ⚠️ `logs/night/RUN.lock` 은 **일부러 커밋하지 않는다**(위 글로브가 `*.log` 인
  이유다). 매 런마다 바뀌는 잠금 상태는 이력에 남길 것이 아니다.
- `logs/night/RUN.lock` 을 **지우지 않는다**(덮어쓴다 · 0절).
- `content/jp/topics.json` 의 `ep` 를 바꾸지 않는다(위 2절).
